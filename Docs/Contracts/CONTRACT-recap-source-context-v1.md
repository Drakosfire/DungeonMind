# Recap source context v1

**Status:** code-only Core read contract. It creates no graph/source data and does not authorize publication.

V1 remains the default discovery and resolution policy. The additive
[V2 contract](CONTRACT-recap-source-context-v2.md) requires explicit discovery
and resolution capability opt-in. A saved `dm-context-anchor:v1:` ID always
reconstructs this V1 selector, including when a newer reader supports V2.
Existing V1 descriptors, ID preimages and product continuation semantics are
unchanged; V2 does not reinterpret V1's canonical H1 requirement.

`WorldGraphRetrievalService.list_source_context_index()` and `resolve_source_context()` expose a separate context-only affordance for recap source revisions. This is not `SourceAnchorMetadata`, claim evidence, or a support citation. The identifier has its own `dm-context-anchor:v1:` namespace. Evidence/support APIs continue to accept only their existing identities; passing a context ID to `resolve_source_anchor()` produces a miss.

The request is a pinned `WorldGraphProjectionRequestV2` with GM admissibility and `WORLD`, `CAMPAIGN`, or `WORLD_CROSS_CAMPAIGN` scope. `WORLD` remains world-owned only. `CAMPAIGN` keeps its exact campaign binding. `WORLD_CROSS_CAMPAIGN` admits campaign-owned provenance across that World in one exact graph revision; it does not silently redefine `WORLD`. At that revision, Core considers only artifact/revision pairs reached from provenance of admitted objects, relationships, assertions, and reviewed source observations. It does not enumerate the source catalog to discover eligible pairs. Each candidate chain is revalidated against the same coherent source snapshot. A pair needs at least one admitted `can_open_source=true` chain; a context token cannot bypass an explicit source-openability denial. The artifact must explicitly declare `session_recap`, World/campaign/session scope must be valid, the source revision must belong to that artifact, and the revision must carry a nonblank URI and full lowercase SHA-256 digest. Opaque `source_domain_key` is never interpreted as a recap classification. Duplicate evidence refs for one pair produce one descriptor. Overflow returns a count and no partial entries.

Each `dm_recap_source_context_v1` descriptor carries the distinct context ID, World/campaign and exact graph revision, source artifact/revision IDs, the revision URI, full content SHA-256, and a typed `dm_recap_context_section_selector_v1`. The selector kind is `recap_section`; policy `markdown-session-recap-v1` binds the source artifact's canonical `session-N` metadata to the exact expected H1 `# Session N Recap`. Core holds no body and asserts no line range. It never derives the section from a filename, opaque legacy span label, source text search, or a different revision.

The product opener must first revalidate the context ID with Core under the caller's exact pinned GM projection. Only then may Buddy open its product-local `repo://` URI, enforce repository containment and symlink refusal, verify the **full revision-byte SHA-256**, decode UTF-8, and find exactly one matching top-level ATX heading. The section begins after that heading and ends before the next same-or-higher heading (the next H1) or EOF. Frontmatter and the heading itself are excluded. Missing, duplicate, ambiguous, or mismatched headings fail closed; there is no whole-document fallback. Buddy computes the actual 1-based range and section digest from verified bytes. Reads remain bounded under the established product max-character policy, with explicit truncation and continuation under the same immutable tuple, never an unlimited or silently truncated read. Its receipt should report exact graph/source pins, selector, actual heading, range/digest, and `context_only=true`. These product-local opening rules are a subsequent Buddy lease, not implemented by Core.

Context ID derivation binds the schema version, World, projection campaign/scope/focus/admissibility, exact graph revision, artifact/revision IDs, the source artifact's own campaign, URI, full digest, and selector identity. The ID is deterministic but **not a credential**. `resolve_source_context()` reprojects and rederives it at read time; forged, foreign-scope, stale-revision, changed-source, and wrong-selector IDs miss. Source standing may change independently of an immutable graph revision, so no cached context ID is authority.

Historical opaque `span:session-*` labels and their evidence/source-anchor semantics remain unchanged and may remain unreadable. A context descriptor allows a user to read a bounded recap section; it is not evidence that any particular historical claim is supported by that section. Claim-specific support requires a separately reviewed digest-bound span/evidence publication.
